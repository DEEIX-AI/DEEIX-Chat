# 平台矩阵

本表定义每项功能在各客户端的可用性，是产品、设计与开发的共同依据。新增功能时先在此确定覆盖范围，再决定 `packages/core` 是否需要新的抽象。

## 列定义

| 列 | 含义 |
|---|---|
| Web | 浏览器访问自托管服务器 |
| 桌面 | 桌面应用连接远程服务器 |
| 桌面（本地） | 桌面应用运行内置服务器的本地模式。与「桌面」列的差异全部由服务器能力声明决定（见 [ARCHITECTURE.md](ARCHITECTURE.md) 第 4 节），客户端不按平台判断 |
| 移动 | 规划中，尚未实现 |

## 状态标记

| 标记 | 含义 |
|---|---|
| 支持 | 完整可用 |
| 部分 | 有限制，备注说明限制内容 |
| 规划中 | 已纳入范围，尚未实现 |
| 不适用 | 按设计不提供 |

## 维护规则

1. 表中未列为支持的组合视为不支持。不因实现成本低而在某一端增加超出其定位的功能；范围一旦模糊，各端会各自演化出不同实现。
2. 新增一行前须回答：逻辑是否需要 `packages/core` 新增抽象；界面是否需要在多端分别实现。逻辑在多端各写一份属于架构违规。
3. 标记为「部分」的单元格必须说明限制内容。
4. 桌面端不新增业务功能行。桌面端等于 Web 端加系统集成能力；出现「桌面端可用而 Web 端不可用」的业务功能，说明抽象放错了层。
5. 「桌面（本地）」列不单独维护功能开关。该列的差异来自服务器能力声明；新增能力位时同步更新此列，而不是在客户端新增平台判断。
